# Лаб — числові методи для жорстких систем

Інтерактивні сторінки до 18 задач розділу 12 «Числові методи розв'язування жорстких систем» і додаткової задачі «Модель Лоренца» (завдання №14 з окремого файлу викладача): розв'язувачі (явний і неявний Ейлер, RK2 — правило середньої точки, RK3 — метод Кутти, RK4, θ-метод, трапеції, BDF2, DOPRI5(4), Розенброк 2(3), адаптивний θ-метод), графіки з різними параметрами, режим «Просто / Науково», покроковий дебагер методу, фазовий портрет, квізи і генератор звіту до лабораторної.

Сторінка Лоренца (`/task/lorenz`) працює з класичною системою Лоренца, а помилки в надрукованій умові (x′ = σ(x − y) замість σ(y − x), y′ = rxy − xz замість rx − y − xz) показує окремо, з перемикачем «як надруковано».

## Інструменти

| Сторінка | Для кого | Що робить |
|---|---|---|
| `/builder` | студенти | Конструктор методу Рунге–Кутти з таблиці Батчера: умови порядку до 5-го, R(z), A- і L-стійкість, карта стійкості, прогін на задачах курсу, перевірка збіжності |
| `/sandbox` | студенти | Своя система ОДР формулами: шаблони, будь-які методи, аналіз жорсткості з рекомендацією методу, експорт коду, посилання на систему |
| `/arena` | студенти | Арена методів: діаграми «похибка — вартість» для всіх 11 методів, теплова карта, рейтинг, висновки з даних |
| `/teacher` | викладач | Генератор індивідуальних варіантів з кодами, ключем відповідей, друком і CSV |
| `/variant` | студенти | Сторінка варіанта за кодом із самоперевіркою відповідей і стартовим кодом |
| `/errata` | викладач | Неточності методички: що надруковано, як правильно, як виявлено, експорт у CSV і Markdown |

На кожній сторінці задачі параметри лабораторії зберігаються в адресі (кнопка «Поділитися»), а кнопка «Код Python / MATLAB» генерує скрипт з поточними параметрами й методами, що повторює алгоритми ядра.

Спільна основа: `lib/expr.ts` (безпечний розбір формул без `eval`), `lib/problem-spec.ts` і `lib/task-specs.ts` (опис усіх 19 задач як даних, звірений зі сторінками), `lib/codegen.ts` (Python і MATLAB), `lib/url-state.ts` (стан у адресі).

Усі обчислення виконуються в браузері, сервер не потрібен: сайт збирається як статичний. Перевірка відповідей на `/variant` теж відбувається в браузері, тому це самоперевірка: для оцінювання викладач звіряє відповіді з ключем.

## Локальний запуск

```bash
npm install
npm run dev
```

Відкрийте http://localhost:3000.

## Збирання

```bash
npm run build
```

Готовий сайт записується в теку `out/` (`output: "export"` у `next.config.ts`). Її можна віддавати будь-яким статичним сервером.

## Деплой на GitHub Pages

Деплой виконує workflow `.github/workflows/deploy.yml` під час кожного пушу в `main`.

1. Створіть репозиторій на GitHub і запуште в нього гілку `main`.
2. У репозиторії відкрийте Settings → Pages і в полі Source виберіть «GitHub Actions».
3. Дочекайтеся завершення workflow у вкладці Actions. Сайт з'явиться за адресою `https://<логін>.github.io/<репозиторій>/`.

Префікс шляху (`basePath`) workflow бере з налаштувань Pages через змінну `PAGES_BASE_PATH`, тому назву репозиторію можна вибрати будь-яку. Локально префікса немає.

Тека `docs/` (наукова робота, скрипти її збирання, копія методички) не входить у репозиторій: її виключено в `.gitignore`.
